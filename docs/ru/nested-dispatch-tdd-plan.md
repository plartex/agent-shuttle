# Контракт контекста worker

Agent Shuttle различает координатора и worker по точному значению `AGENT_SHUTTLE_PARENT_CONTEXT=worker`. Маркер устанавливается после пользовательских настроек окружения; транспортные токены координатора в окружение worker не включаются.

Роль сохраняется на время жизни экземпляра. Вложенный MCP и A2A отклоняют новую делегацию, отмену задач и другие операции координатора до изменения состояния. Описание инструментов дополняет эту проверку, а ограничения файловых операций обеспечивает выбранная агентская среда.

Чтение статуса, результата, событий и метаданных остаётся доступно в пределах соответствующего API. Состояние вложенного экземпляра хранится отдельно в `nested/`, чтобы завершение его процессов не затрагивало задачи координатора.

Docker-адаптер в worker-контексте запускает собственный локальный stdio MCP с тем же запретом вложенной делегации. Он не подключает worker к общей службе координатора.

Реализация: `runtime_context.py`, `mcp_server.py`, `mcp_gateway.py`, `a2a_server.py`, `task_library.py`. Проверки: `tests/test_nested_context.py`, `tests/test_mcp_commands.py`, `tests/test_mcp_gateway.py`. Гарантии политики каждого harness проверяются через `get_agent_info`; advisory-политика ACP не является файловой песочницей.
